# C01 고객별 S1~S5 브리핑 초안과 기반지식

**고객 DATA·세그먼트·대화 → 솔루션 방향 → 원문 기반지식**을 연결한 자료와, 이를 바탕으로 작성한 **12명 전원의 S1~S5 브리핑 초안**을 함께 보관한다. 김서연(C01-10) 작성본의 구성과 말투를 기준으로 나머지 11명도 고객별로 작성했다.

고객 폴더의 **`briefing_draft.md`는 검토할 문장**, **`knowledge_pack.md`는 고객 DATA·대화·원문 발췌**다. 초안에는 S3 상품 후보, S4 고객 반응별 화법, S5 Hot Tip 원문 링크·단말 화면번호, 출처 Git 링크를 넣었다. 현재 검토용 Markdown 단계이며 앱 화면에 쓰이는 브리핑 JSON에는 반영하지 않았다.

입력: [C01_고객DATA_대화_원문매핑.json](<../../../../C01_고객DATA_대화_원문매핑.json>) · SHA-256 `afb4e429b5966de8e4c936a8c17160bec1d3a2ca2f04c8f7626e882a60996606`
대상: C01-01~C01-12, 12명 · 고객 기준일 2026-09-29 · 작성일 2026-09-21. 기준일은 입력 데이터의 시연 기준일이며 작성일과 구분한다.

**한 명씩 검토:** 아래 표의 **브리핑 초안**부터 열고, 문장의 근거나 원문을 더 보고 싶을 때 같은 고객의 **기반지식**을 함께 읽으면 된다. GPT 웹에서 이어갈 때도 해당 고객의 두 파일을 함께 첨부하면 된다. 각 출처의 **Git 원문**은 `41ae9a44357ccabde98dec76d99965e6b038b2a6`에 고정했고 발췌/화면 근거에는 줄 번호를 붙였다. GitHub 접근 권한이 필요한 경우에도 기반지식 파일 안의 발췌를 읽을 수 있다. 초안·기반지식·입력 JSON은 저장소에 함께 보관하며, 아래 상대 링크는 로컬과 GitHub에서 같은 파일을 가리킨다.

## 사용하는 순서

먼저 `briefing_draft.md`의 S1~S5를 검토한다. 초안 뒤의 상품 설명·근거·검토 메모에서 적용 조건과 미확인 사항을 확인할 수 있다. 아래는 같은 고객의 `knowledge_pack.md`에서 원문을 찾아보는 순서다.

1. 고객 파일의 **1절 데이터·세그먼트·대화 검토사항**에서 확정할 수 있는 사실과 추가 확인사항을 읽는다.
2. **2절 솔루션 방향**을 출발점으로 삼고, 원문의 판단 이유·조건·예시를 읽어 S2를 구성한다.
3. **3절 S3**에서 상품별 역할·선택조건을 비교한다. 보유 유지, 상품 교체, 전략 변경, 향후 설정 변경을 구분한다. 상품 마스터 원문 레코드를 펼쳐 상세 근거를 확인할 수 있다.
4. **4절 S4**의 원문 문단을 바탕으로 이름·금액·날짜·만기 전후를 조정한다. 원문의 예시 고객 반응을 실제 발언으로 쓰지 않는다.
5. **5절 S5**에서 해당 솔루션에 필요한 업무만 선택한다. 단말 화면의 기능과 Hot Tip의 활용 이유·게시글 원문 링크·발췌를 함께 읽는다.
6. **7절 부록**에는 해당 고객 DATA 전체와 연결된 모든 개별 Q&A를 보존했다. 반복·오류가 있는 답변도 원문을 고치지 않았다.

## 자료를 읽을 때 구분할 것

- **검색 범위:** 입력 JSON의 고객별 대화와 공통 타겟 구간을 사용했다. 공통/미매핑 행 82건은 입력에 행 번호만 남은 범위가 있어, 전체 대화 164행을 빠짐없이 읽어 매핑한 자료라는 뜻은 아니다.
- **고객 사실:** 입력 JSON `display_data`. 현재 저장소의 해당 C01 원본과 12건 모두 구조적으로 동일함을 확인했다. 명백한 불일치가 있는 플래그도 임의로 수정하지 않았다.
- **대화 제안:** 상담준비 Agent의 실측 답변. 고객의 실제 발언·현재 의향·공식 규정으로 승격하지 않았다. 소득구간을 바꿔 보는 질문들은 서로 다른 가정 분기다.
- **원문 발췌:** Source Registry를 경유하여 관련 MD 절을 읽고 연속된 문단을 보존했다. PDF/이미지/영상 원본 자체를 다시 검수한 것과 구분한다. KB Think MD는 웹 원문을 정리한 자료임을 표시했다.
- **상품·전략 매핑:** `SRC-100`의 선택 논리는 자료 기반 기획 해석, `SRC-099`는 상품자료 정리본이다. S01~S05 원 상품파일 실물은 저장소에서 찾지 못해 상품 마스터 레코드까지 확인했다. 현재 판매가능·법규 적합성·거래 가능성은 미검증이다.
- **솔루션 방향·연결 이유:** 이번 고객 DATA와 출처를 연결한 작성용 가설이다. 원문과 별도 표시했고 최종 선택은 작성자가 한다.
- **뱃지·고객 맥락:** 현재 뱃지와 상담이력을 사용하고 나이·자산구성·수익률에서 읽은 의미는 해석으로 표시했다. 데이터에 없는 앱 방문이나 다른 계좌 매수는 실제 행동으로 추가하지 않았다. 일부 초안의 추가 뱃지 제안은 해당 로그가 확보될 때의 조건부 아이디어다.
- **편집 화법:** S4는 원문의 설명 순서와 주요 표현을 고객 상황에 맞춰 다듬은 상담 예시다. 원문은 기반지식 파일에 보존했고, 오래된 수치·근거 없는 성과/판매상태 단정은 초안의 확정 문장으로 옮기지 않았다.

## 검증 범위

**기반지식:** 고객별 DATA 12건, 개별 Q&A 125건·공통 발췌 3건, 지식 원문 발췌 93곳, 상품 원문 레코드 35개, 화면 매핑 87개를 입력/원문과 대조했다. 기반지식의 Git 링크 437개는 고정 커밋의 파일 내용·줄 범위·앵커와 대조했다(중복 참조 포함).

**브리핑 초안:** 김서연 포함 12건의 S1~S5 구성·고객명 분리·상담 분기·로컬 링크/앵커를 확인했다. 초안의 Git 링크 286개가 가리키는 31개 원본 파일은 고정 커밋과 내용이 일치하고, 인용 줄 범위가 존재함을 확인했다. 새로 작성한 11건의 상품 매핑 33개, 화면 매핑 80개, Hot Tip 연결 14개를 연결 원문과 대조했다. GitHub 로그인·사내 화면 실행·Hot Tip 로그인 접속을 검사한 것은 아니다.

**저장소 확인:** `node tools/briefing/build.js`, `node tools/briefing/check.js` PASS. 이 검사는 기존 실행 데이터와 화면 구조에 대한 검사이며, 이번 Markdown 초안의 문장 적정성을 자동 보증하지 않는다. 입력 JSON의 SHA-256과 고객 원본·지식 원본은 그대로 유지했다. 실제 판매조건·금융 솔루션의 최종 적정성은 고객별 검토 항목에 남겨두었다.
