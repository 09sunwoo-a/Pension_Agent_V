# Dynamic Segment 뱃지 카탈로그 (39종)

메인 목록 뱃지의 유일한 출처입니다. 고객 JSON `signals[].label`과 레거시 행(`pensionAgentDemo.js`의 QMETA)은 이 목록 안의 문구만 사용합니다. 색·분류·정렬은 `frontend/src/briefing/pensionCustomerView.js`의 CATEGORY 표가 결정하며, 이 문서와 코드가 다르면 코드를 고친 뒤 이 문서를 맞춥니다.

사용 현황 기준: 42케이스(`active/display-data/B*.json` 30 + `C01-*.json` 12), 기준일 2026-09-29. 괄호 안은 레거시 15행에서 추가로 쓰인 수. 이 문서는 마지막 갱신 시점의 스냅샷이며 고객 JSON을 고치면 다시 집계합니다.

## 원칙 요약

- 뱃지는 고객의 현재 **상태·이벤트·행동**(Fact/Signal)이다. `리밸런싱 필요`, `ETF 추천`, `상담 필요` 같은 판단·추천은 S2/S3 영역이므로 넣지 않는다.
- 각 JSON 안의 데이터(`customer`, `irpAccount`, `holdings`, `에이전트맥락데이터`)로 확인되는 사실만 근거로 한다. 시연용으로 추가한 근거는 `에이전트맥락데이터`에 넣고 `가상설정메모`에 가정을 남긴다.
- D-day는 시스템 날짜가 아니라 해당 JSON의 `briefingMeta.asOfDate`로 계산한다.
- 한 고객에 1~3개. 억지로 채우지 않는다. 같은 의미의 뱃지(`현금성 과다`/`현금성 장기대기`, `올해 미납입`/`납입 중단`)는 더 구체적인 쪽 하나만 쓴다.
- 제외: 관리등급, 연령, SOHO 등 고객속성, 급여이체, 세액공제 여력, 상담 선호, 추천상품, 관리방향.
- 새 뱃지명을 임의로 만들지 않는다. 카탈로그 변경은 이 문서와 CATEGORY 표를 함께 고친다.
