# 부점 AI 구현 기획·골든셋

갱신: 2026-09-20. 목표는 **사내 시연 완료**. 프론트 시연에 아래 골든 흐름을 반영하고 로컬 검증했다. 실제 부점 Agent·사내 E2E는 다음 단계다. 현재 코드 상태는 [AS-IS](BRANCH_AI_FRONTEND_AS_IS.md). 구현할 때는 이 문서와 해당 코드만 먼저 읽는다.

실제 Agent 전환은 [세션별 작업 안내](branch-agent/README.md)에서 계약·프론트 연결·데이터·로직/멀티턴·출력 골든·사내 검증으로 나눈다. 아래는 기능·기대값의 원본이며 API 필드 정의를 중복하지 않는다. 지정 모델은 `gemma-4-31b-it`, 배포/검증은 신규 `branch-agent/`에서 분리한다.

## 1. 확정 방향과 남은 결정

- **사용자 지정:** 검색 답변에 ‘김형준·이수민… 고객을 찾았습니다’처럼 이름을 나열하지 않는다. 인원·조건·필요한 집계만 답하고 고객은 메인 목록에서 확인한다. 특정 고객 브리핑·대상 구분에는 이름을 사용한다.
- **사용자 지정:** ‘오늘 중점적으로 관리할 고객은 누구야?’ → 정미경·신경호·오민서 추천. ‘오늘 부점 현황 말해줘’ → 부점 통계 요약. 서로 다른 의도다.
- **사용자 지정:** 개별 답변은 현재 상황 + 그에 따른 관리 방향을 2~3문장으로 요약한다.
- **진행 순서:** 골든 초안 검토 → 프론트 시연 구현 → 골든 확정 → Agent 로직·계약 계획 → 실제 Agent 구현·사내 연결 검증.
- **프론트 반영:** 일반 집계는 목록 유지/‘대상 보기’로 연결한다. 검색·추천은 목록 변경, 개별 브리핑은 유지한다.
- **프론트 반영:** ‘운용금액’은 IRP 평가금액 기준인지 선택으로 확인한 뒤 조회한다. 자동 별칭으로 단정하지 않는다.
- **사용자 지정:** 원래 메인 상단·고객 카드 구조를 유지한다. 새 근거·간단 브리핑·조건 조작·0명 복구 행동은 대화창 안에만 둔다. 검색/추천의 기존 행 선택·순서 변경은 유지한다.
- **프론트 반영:** 새 대화의 목록/추천 상태 보존. 자동 알림·전일 변화 계산·100명 페이지·추천 등급 확대는 후속 범위다.

## 3. 기능별 골든셋

## 4. 구현 순서·완료 기준

1. **문구(반영):** 일반 검색의 이름 나열·고객별 자동 상세줄 제거. 인원·정렬 제한·집계·미확인은 유지.
2. **프론트(로컬 검증):** 시작 질문 3개·근거 추천·간단 브리핑·조건 조작/복원·명확화·통계 목록 유지. 기존 스켈레톤·900ms 등장 효과 재사용. 메인 상단·고객 카드 원형 유지, 새 정보·행동은 대화창 안에만 표시.
3. **골든 사용자 검토:** 표의 정확 문장과 동의어를 실행해 질문 의도·결과 ID·수치·목록 효과 검증. 일반 ISA 3명/30일 내 1명/오늘 만기를 혼동하지 않기.
4. **Agent 계획:** 근거 투영·선정/집계 코드·LLM 질문 해석/문장화·대화 상태·응답 계약·취소/오류 설계. 현재 S1~S5 고정 Agent와 부점 AI는 별개다. 기존 CHAT 계약을 그대로 전용하지 않는다.
5. **사내 시연:** 실제 FabriX 호출·인증·Starroot/WAS 환경에서 골든 실행. 로컬 PASS와 사내 E2E를 구분하고 미검증은 명시한다.

검증은 `node tools/briefing/build.js`, `node tools/briefing/check.js`(기존 검사+`tests/branch-search/conversation.test.js`). 화면 검사는 미리보기와 테스트 Chrome 실행 후 `node tools/briefing/check-briefing-browser.js`. Agent 변경 때만 `--agent` 추가, HTTP SKIP은 명시. 구조 PASS를 금융 내용 검토나 신규 기능 완성으로 취급하지 않는다. 요청 없는 commit/push/사내 배포 금지.
